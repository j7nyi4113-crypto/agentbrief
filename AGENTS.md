# AGENTS.md

Instructions for coding agents working in this repository.
The **Repo facts** block at the bottom is generated by [agentbrief](https://github.com/j7nyi4113-crypto/agentbrief)
and verified in CI. Run `agentbrief update` after changing commands or moving files.
Everything above the block is yours — that is the part no tool can write for you.

## What this is

`agentbrief` keeps AGENTS.md honest. It reads a repository's manifests, lockfiles and CI
workflows, writes the verifiable facts into a managed block, and re-checks them later.
Zero dependencies, plain ESM, Node 18+. "Done" means: `npm test` passes and
`node bin/agentbrief.js check` exits 0 on this repository.

## How to work here

- No build step and no dependencies. Adding one needs a very good reason.
- `src/ecosystems.js` owns detection. Every command it emits must carry a `src` pointing at the
  file that proves it — `check` follows that pointer to decide whether the fact still holds.
- `src/render.js` owns the markdown. The block layout is a contract: begin marker, one
  `agentbrief:meta {json}` line, then human-readable tables.
- Tests use `node:test` only. Add a fixture under `test/fixtures/` for every ecosystem you touch.
- Error messages are lowercase and actionable ("run `agentbrief update`"), never apologetic.

## Traps

- `fs.cpSync` crashes the Node process on Windows here. Tests copy directories by hand
  (`copyDir` in `test/check.test.js`). Do not reintroduce `cpSync`.
- `node --test` auto-discovers `test/fixtures` and tries to execute the `.ts` fixture. Always use
  the explicit glob in `package.json`.
- The meta schema is versioned. Bump `v` before changing its shape, and keep `check` able to read v1.
- This file is generated by the tool itself. After changing a script or moving a directory, run
  `node bin/agentbrief.js update`, or CI fails on purpose.
